# ADR-001 · 采用对标物的设计令牌数值（不取代码）

- **日期**：2026-11-25
- **状态**：`accepted`
- **决策者**：项目负责人
- **关联工作项**：`P0-01`

## 背景

本项目的 UI 质量目标是「与成熟机构级终端同级」。从零设计一套色彩/字体/图表调色板，
在以下三件事上会明显低于已有方案：

1. **12 色序列调色板的色觉障碍可辨性** —— 需要相邻对两两做 CVD 模拟校验，
   手工调参很难达到可用水平；
2. **双主题（暗/亮）的完整语义角色覆盖** —— 需要 `bg`/`border`/`text` 各三到四档 +
   `positive`/`negative`/`warning`/`info` + 淡填充 + 表格斑马 + 序列色，缺一档就会
   在某个场景退化为硬编码色值；
3. **等宽字体在密集数字场景的可读性** —— 财经表格的小数位对齐是硬需求。

对标物 FinceptTerminal（AGPL-3.0-or-later）在其公开源码中完整发布了这套令牌。

## 候选方案

| 方案 | 优点 | 缺点 | 代价 |
|---|---|---|---|
| **A. 移植令牌数值** | 一次到位；CVD 校验已由上游完成；双主题完整 | 与 AGPL 项目有「参照关系」，需明确许可边界 | 低 |
| B. 从零自研 | 无任何许可顾虑 | 需自行完成 CVD 校验与双主题补全；至少数周迭代 | 高 |
| C. 用现成设计系统（如 Ant Design / Radix） | 生态成熟、组件齐全 | 面向企业后台而非高密度金融终端；表格密度、数字排版、12 色序列均需大量覆写 | 中高 |

## 决定

**采用方案 A**，但严格限定范围：**只取「数值型设计参数」**，即
色彩十六进制值、字体族字符串、字号基准（14）、图表调色板 12 色序列及其顺序、色盲变体取值。

**明确不取**：
- 任何源代码（C++/Python/CMake/QSS/JS）
- 图标、图片、字体文件本体（字体仅声明字体族名，由用户环境提供）
- 文案、注释、界面标签
- 组件结构、交互逻辑、视觉布局（这些由本项目依据 `DESIGN_SYSTEM.md` 自行设计）

**理由**：色彩值、字体名、调色板序列属于**功能性事实数据**（与「某个颜色叫琥珀色」同类），
不构成表达性作品；而上述「不取」清单覆盖了著作权保护的表达性部分。同时本项目为 MIT 许可、
不分发对标物任何产物，不构成 AGPL 意义上的衍生作品或向公众提供。

**此外**：`DESIGN_SYSTEM.md` 明确标注哪些令牌是「移植」、哪些是「自定」。
凡自定部分（间距、圆角、动效、字号阶梯、布局断点、键盘映射），全部由本项目独立确定，
不来自对标物。

## 后果

### 变好的

- 双主题与 12 色序列一次到位，CVD 可辨性有上游校验背书
- 数字排版密度直接对标机构级终端，省去数周调参
- 令牌清单明确，`check_tokens` 可机械校验

### 变差的（诚实列出）

- 引入了一个「参照关系」，需要在 README 与 LICENSE 中如实声明（已做）
- 若对标物后续调整令牌，我们没有自动同步机制（也不需要——令牌一旦自定即为本仓契约）
- 移植的色彩是**西方习惯的绿涨红跌**，与 A 股相反。已通过拆分
  `--wb-up` / `--wb-down` 独立令牌解决，默认 A 股习惯

### 不可逆的部分

一旦组件消费了这些令牌，更换色彩体系等于全局重构。因此 `DESIGN_SYSTEM.md` §13 规定：
改令牌需改基线 + 更新全部视觉基线截图 + 记一条 `refactor` 工作项。

3. 若上游令牌在新版本中显著变更，且我们认为新版更优，走一次设计系统变更流程
